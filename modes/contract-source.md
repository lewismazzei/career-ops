# Mode: contract-source -- Contract-First Sourcing

Find and triage leads where the likely next step is a conversation about paid remote work, not a traditional job application pipeline.

## Good Sources

Prioritize:

- freelance marketplaces with current client posts;
- paid trial and fixed-price project boards;
- buyer-intent posts from founders, operators, agencies, and small businesses;
- community "looking for help" threads;
- open-source bounty boards with an active maintainer/contact path;
- referral leads where a bounded first paid step is plausible.

Use broad remote job boards only as fallback inventory.

## Real Opportunity Test

A candidate is real only if it has:

1. Visible buyer or buyer proxy.
2. Concrete paid need.
3. Plausible path to a conversation.
4. Remote deliverability.
5. Bounded first paid step.
6. Current source evidence.

Reject or demote candidates that are only traditional applications, unpaid speculation, vague networking, content farms, scams, or unbounded "partner" requests with no near-term payment path.

## Batch Acceptance

A sourcing batch is not good enough until it contains at least five real opportunities, and at least three of those must come from non-generic-job-board lanes: freelance marketplace posts, buyer-intent posts, bounty boards, agency overflow, referral leads, or outbound target briefs.

For each counted candidate, record why the first conversation could plausibly discuss paid scope, budget, timing, trial work, or a commercial next step. Do not count "could apply" as enough.

When the batch is explicitly correcting a source-concentration problem, the dominant source being corrected does not count toward the five. A diversification batch should include at least two source families unless the user explicitly asks for a single replacement source.

## Required Output

For each accepted candidate, capture:

| Field | Meaning |
| --- | --- |
| Source | marketplace, community, referral, bounty, outbound, or other |
| Buyer/Target | visible buyer, company, project, or maintainer |
| Need | concrete paid need |
| First paid step | paid trial, fixed deliverable, hourly contract, sprint, audit, retainer pilot, bounty |
| Conversation path | how the operator can start a conversation |
| Remote fit | async-global, timezone-overlap, country-bound, or unknown |
| Evidence | URL plus key facts from source |
| Risks | competition, weak fit, low budget, unclear buyer, platform friction |
| Next action | the immediate Codex/operator move |

## Output Rule

Do not let "contract" labels alone pass. A contractor-labelled role with a normal application/interview pipeline is lower priority than a small live project with a clear buyer, even if the latter is outside software.
