# Mode: scythe -- Discovery

Show the Scythe command menu and explain which mode to use next.

## Menu

```text
Scythe -- Remote Paid-Work Acquisition

Available modes:
  scythe opportunity {listing/JD/gig/URL}
      Evaluate any posted opportunity for remote execution, agent leverage, proof match, economics, and next action.

  scythe target-brief {target/person/business/URL}
      Produce a one-page outbound opportunity brief from visible intent plus an execution gap.

  scythe contract-source {marketplace/search/community/referral surface}
      Source and triage contract-first leads where the natural next step is a paid-work conversation.

  scythe v0-launch {idea/project/target}
      Evaluate whether an idea or target can move from ambiguous need to first real customer in a bounded paid sprint. This is a high-upside lane, not the default first pursuit.

  scythe scan
      Monitor broad remote boards. This is fallback inventory, not the primary contract-acquisition engine.

  scythe pipeline
      Process queued opportunities from data/pipeline.md into data/opportunities.md.

  scythe tracker
      Summarize opportunity state, follow-ups, and conversion signals from Scythe trackers.
```

## Positioning

Scythe is not a generic freelance scraper. It ranks any paid remote work by:

- time to cash
- remote executability
- agent leverage
- credible proof match
- path to paid conversation
- economics and repeatability
- risk and validation path

If the user asks what to run first, recommend:

1. Source 10-20 contract-first leads from contract marketplaces, buyer-intent posts, agency/operator overflow, referral paths, or specific outbound targets.
2. Use broad remote job boards only as fallback inventory or for unusually attractive contract roles.
3. Run `scythe opportunity` on posted contract/project/referral leads.
4. Run `scythe target-brief` for outbound targets with visible intent and a bounded execution gap.
5. Track replies, qualified conversations, and path to payment before optimizing the system.
